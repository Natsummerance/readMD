What changed in ReadMD v2.3.8.

ReadMD v2.3.8 is the first stable release published through the self-use channel. It unifies batch conversion in one cancellable workbench, parses PPTX and XLSX natively, hardens chart and archive handling, and completes the 46-language interface.

Release highlights and boundaries

  1. One batch workbench

    Conversion, OCR, and export jobs share a unified workbench where any task can be cancelled and every result row stays traceable.

  2. Native OOXML parsing

    PPTX and XLSX import reads the files directly, while legacy Office formats fail with a clear message instead of a cryptic error.

  3. Hardened charts and archives

    Zip extraction rejects path traversal and archive bombs, Vega and Vega-Lite render in a server-side sandbox with no unsafe-eval, PlantUML asks before remote rendering, and Chart.js renders offline.

  4. 46 languages and calmer tooling

    Interface text from the system tray to skill imports ships in 46 languages; VS Code and MCP gain dynamic skills, streaming cancel, and connection status, while skill imports roll back automatically on failure.

v2.3.8 release questions

Is v2.3.8 a stable release?

Yes. v2.3.8 was published on GitHub as a stable release, not a prerelease, on 2026-09-03. It ships via the READMD_SELF_USE_RELEASE self-use channel: assets are unsigned and the native platform evidence list is informational, so keep backups and verify SHA256SUMS.txt before installation.

Does display repair change my Markdown?

No. Rendering repairs affect the in-memory display. Source bytes change only when you explicitly edit and save the document.

How are updates checked?

Updates come from official GitHub Release assets into a fixed directory, use temporary files and SHA-256 verification, then publish atomically and recheck before execution.

Which platforms receive packages?

Stable packages target Windows 10/11 (x64/ARM64), macOS 13+ (Intel and Apple Silicon), and Linux x86_64/ARM64 on Ubuntu 22.04/24.04 and Debian 12. UOS, Kylin, and Deepin still lack native evidence and are not formal support commitments; HarmonyOS/OpenHarmony is out of scope for v2.3.8.
