# ReadMD v2.2.3 导出、网页转换与重命名设计记录

## 目标

修复 Windows 保存对话框返回单元素 tuple 导致三种导出格式共同失败的问题；提高网页正文提取对动态站、短公告和文档页的覆盖；让当前本地 Markdown 文件可从顶栏安全重命名。

## 关键决策

- 所有保存路径先经过同一标准化入口，目标文件使用同目录临时文件生成并通过 `os.replace` 原子提交。
- 静态网页依次使用 Trafilatura 标准/recall；系统 WebView 渲染后依次使用离线 Defuddle 0.19.2、Mozilla Readability、语义容器和清理后的完整页。
- Defuddle 以固定 Bundle 和 MIT 许可证随应用分发，`useAsync=false`，运行时不访问第三方提取服务。
- 动态抓取临时窗口不注入 ReadMD JS API；先在空白页安装 WebView2/WKWebView 原生网络守卫，再导航到目标页，未授权私网请求会在发送前阻断；交互会话结束销毁窗口并清理 Cookie。
- 内网页面默认禁止。桌面桥接仅在用户勾选后签发绑定 task ID、origin、随机令牌且 10 分钟过期的授权；HTTP/LAN 接口不能签发。
- 重命名仅修改原目录内的文件名主体、保留受支持扩展名且绝不覆盖；成功后以真实新路径为准，同步偏好与历史失败只显示警告。

## 发布门

Windows、Intel macOS 与 Apple Silicon macOS 均执行 Python 回归、Playwright、`--selftest`、资源检查和隐私扫描。Windows 冻结包显式收集 python-docx、ReportLab、Matplotlib、Trafilatura；两种 macOS 架构验证 Bundle 版本和 Defuddle/Readability 资源。仅标签 `v2.2.3` 的统一 Release job 可发布四个资产。
