## 本轮新增实现

1. Vega/Vega-Lite 通过固定脚本和 vendored bundle 在本地 Node 进程生成 SVG；浏览器 CSP 不需要开放 `unsafe-eval`。
2. 其他图表引擎继续走按需浏览器渲染；不具备本地运行时的 D2/PlantUML 明确返回不可用或在线渲染状态，不伪报成功。
3. 图表能力接口现在按安装实例探测静态资源、Node 和本地 PlantUML；PlantUML 远程加载失败时预览会回退到安全源码提示，不再显示破损图片。
4. 冻结构建只接受随包的 Node 运行时；开发机 PATH 中的 Node 不会把缺少运行时的正式包误报为 Vega 可用。
5. 增加 Hermes 兼容的本地宠物目录、受限导入/列表/删除/激活 API；导入仅接受 PNG/WebP、大小和路径均有限制。
6. 代码块 `output=true` 可将标准输出作为受控标记回写文档，并复用正常保存/历史路径。
7. Skill 导入与生成失败仅显示本地化文案，不再把后端错误码、原始异常或中文兜底写入工作台。

## 尚未闭环的发布阻断项

### 图表与离线能力

- 未提供 D2 本地运行时；D2 只能显示安全错误。
- PlantUML 默认仍是在线 URL；只有检测到本地 Java/JAR 才能离线。
- Chart.js 已接入独立代码块 dispatcher，并通过 Chromium desktop/mobile 离线 canvas 回归；当前尚无每个引擎在正式打包应用中的冷启动截图/视频证据。

### 桌宠

- `src/readmd_modules/pet/store.py` 只负责安全的本地资源目录和 API。
- Hermes 适配器是可选插件，尚未形成主应用内置的完整桌宠 UI/平台闭环。
- 没有当前提交在 macOS/Linux 原生透明窗口上的真实证据；不能宣称这些平台已验证。
- Cubism Core/模型再分发许可仍需在正式资产中逐项确认。

### 生态与本地化

- VSCode 仍有运行时中文消息和硬编码 workflow，尚未建立完整 `package.nls.*` 体系。
- VSCode 目前只有 8 个自动测试，未覆盖声明的全部命令、流式取消和真实 Core 生命周期。
- MCP 尚无 Claude、Cursor、Cline 的当前提交端到端连接证据。
- Playwright 当前仅有 Chromium 项目；Firefox/WebKit、200% 缩放和完整 RTL 证据尚缺。
- 46 个 locale 只完成结构门禁；外围 UI 的逐条语义审校和长文本人工验收未完成。
- 主要 HTTP 转换、OCR、网页、上游来源和 AI 历史路径已收敛为稳定 `error_code`；仍有旧的 pywebview 兼容桥接分支返回本地化错误文本，需要在发布前继续统一。

## 结论

当前分支适合作为继续修复和本地 Preview 的基础，但不是正式候选：仍存在 P1/P2 级功能与证据缺口。任何“全平台可用”“全部离线”“正式发布”表述都必须等上述阻断项有当前提交、真实环境和可追溯产物后再使用。

下一步应在本分支继续完成错误码收敛、Skill/宠物路径安全加固、真实文件转换与压力测试，并重新生成带 commit 和 SHA-256 的 Preview 证据包；在用户验收前不合并 `main` 或发布。
