## 3. 两个失败用例——根因 + 修复（核心）

> 已读源码确认。源码真身在 `assets/js/features/ai.js`（bundle `assets/readmd.boot.js` 是生成物，行号会漂移，以 grep 函数名为准）。

### 3.1 失败 A：`provider search input filters provider cards`（spec 第 51–68 行）

**症状**：`await expect(page.locator('#ai-provider-cards .ai-provider-card')).toHaveCount(2)` 拿不到 2。

**根因（已确认）**：**初始化竞态覆盖**。
- `fillAiProviders(merged, current)`（boot ~9140；源 `ai.js`）确实会渲染卡片：`cards.innerHTML=''` 后按 `#ai-provider-search` 的值过滤 `merged.concat(state.ai.upstreamCatalog)`，卡片 class 以 `ai-provider-card` 开头（boot ~9166）。逻辑本身正确。
- 但 spec 在 `page.goto('/')` 后只 `waitForFunction(typeof fillAiProviders==='function')`（函数一解析完就满足），随即**同步** seed `state.ai.providers=[openai,deepseek]` 并调用 `fillAiProviders` → 渲染出 2 张卡。
- 与此同时，App 自身启动时的**异步** `loadAiConfig()`（fetch `/api/ai/config`）在**之后**才 resolve，把 `state.ai.providers` 覆盖成真实配置（沙盒是全新 temp 数据目录 → **空**），并再次调用 `fillAiProviders` → 卡片被重渲染成 **0 张**。
- 后续 `fill('deepseek')` 触发 `#ai-provider-search` 的 input 监听（`app.js:550`：`fillAiProviders(state.ai.providers||[], …)`），此时 `state.ai.providers` 已被覆盖为空 → 仍 0 张。断言稳定失败。

**修复（改 spec，最小且稳）**：seed 之前**先等 App 的异步配置加载完成**，消除覆盖竞态。`loadAiConfig()` 会置 `state.ai.config`（`ensureAiConfigured` 里 `if(!state.ai.config) await loadAiConfig()` 可反推）。把 test 3 开头改成：

```js
test('provider search input filters provider cards', async ({ page }) => {
  await page.goto('/');
  await page.waitForFunction(() => typeof fillAiProviders === 'function');
  // 等 App 自身 loadAiConfig 完成，避免其异步回调覆盖我们 seed 的 providers
  await page.waitForFunction(() => window.state && state.ai && state.ai.config, null, { timeout: 15000 });
  await page.evaluate(() => {
    state.ai.providers = [
      { id: 'openai', name: 'OpenAI', note: 'GPT presets', custom: false },
      { id: 'deepseek', name: 'DeepSeek', note: 'deepseek-chat', custom: false },
    ];
    state.ai.upstreamCatalog = [];
    fillAiProviders(state.ai.providers, { provider_id: 'openai' });
  });
  await expect(page.locator('#ai-provider-cards .ai-provider-card')).toHaveCount(2);
  await page.locator('#ai-provider-search').fill('deepseek');
  await expect(page.locator('#ai-provider-cards .ai-provider-card')).toHaveCount(1);
  await expect(page.locator('#ai-provider-cards')).toContainText('DeepSeek');
  await page.locator('#ai-provider-search').fill('');
  await expect(page.locator('#ai-provider-cards .ai-provider-card')).toHaveCount(2);
});
```

- 若 `waitForFunction(state.ai.config)` 超时（说明该 flag 名不对），退路：grep `ai.js` 里 `loadAiConfig` 看它把配置存到哪个字段（可能是 `state.ai.config` / `state.ai.providers` 已填充 / 某 `loaded` 标志），改成等那个条件；或退而用 `await page.waitForLoadState('networkidle')`（注意：若有轮询会 hang，优先用 waitForFunction）。
- **不需要改 App 代码**——这是 spec 的时序 bug，不是产品 bug（产品里用户是先打开设置弹窗、配置已加载后才操作搜索框，不会遇到此竞态）。

### 3.2 失败 B：`two-step AI creation validates fields and routes unconfigured users to AI settings`（spec 第 70–87 行）

**症状**：流程走到最后，`#ai-settings-modal` 没变可见。失败快照显示：Skill 工作台 dialog 开着、「AI 生成」按钮在、但**没有第二个 dialog**（既无 `skill-create-modal` 也无 `ai-settings-modal`）。

**先做**：单独复跑抓精确断言行（见 §0 命令）。两种可能失败点：

- **若失败在第 74 行**（`#skill-create-modal` 未打开）：说明点 `#tpl-ai-generate` 没触发 `openSkillIdeaDialog`。排查：
  - `#tpl-ai-generate` 绑定在 `app.js:576`（`addEventListener('click', generateSkillDraft)`），按钮是静态 HTML（`index.html:630`），`openTplModal` 不会销毁工具栏绑定（旁证：test 5 点 `#tpl-import-btn` 通过，绑定同在工具栏）。所以绑定应在。
  - 挂 `page.on('pageerror', …)` / `page.on('console', …)` 看点 `#tpl-ai-generate` 后是否抛错。
  - `generateSkillDraft`（boot ~8100）：`if($('skill-create-modal')){ const idea=await openSkillIdeaDialog(); … }`；`openSkillIdeaDialog`（boot ~8043）末尾 `modal.classList.remove('hidden')`。确认 `#skill-create-modal`（`index.html:662`，初始 `class="modal hidden"`）无重复 id、无 CSS 让它即使去掉 hidden 仍不可见。

- **若失败在第 86 行**（`#ai-settings-modal` 未打开，**更可能**，因快照里 skill-create-modal 已关闭=流程走过了 onGo）：根因在 `ensureAiConfigured`（boot ~9222；源 `ai.js`）：
  ```js
  async function ensureAiConfigured() {
    if (!state.ai.config) await loadAiConfig();
    const pending = currentAiProvider();
    if (pending && !pending.credential_id && $('ai-key').value.trim()) await saveAiSelection(true);
    const connection = await resolveSharedAiConnection();          // ← 嫌疑 1
    if (connection && (connection.local || connection.has_key)) return connection;  // 若这里 truthy 就直接 return，不开设置
    showToast(_t('toast.noApiKeyNotice'), 2800);
    if (typeof openAiModal === 'function') openAiModal('ai-settings-modal', $('ai-settings-open'));  // ← 嫌疑 2
    return null;
  }
  ```
  **两个嫌疑，逐一验证**：
  1. **`resolveSharedAiConnection()` 在全新 temp 数据目录里错误地返回 `connection.local` 为 truthy** → 提前 `return connection` → 永不开设置弹窗，`generateSkillDraft` 继续去 POST `/api/skills action:generate` 失败弹 toast。验证：在沙盒/测试环境打印该函数返回值。若确认，修 `resolveSharedAiConnection`：无 key 无 local 时必须返回 `{local:false, has_key:false}`（或 null）。
  2. **`openAiModal('ai-settings-modal', $('ai-settings-open'))` 在浏览器模式空转**：`$('ai-settings-open')` 这个 opener 元素可能为 null，或 `openAiModal` 依赖 pywebview/桌面态才 remove hidden。验证：读 `openAiModal` 源码（grep `function openAiModal`）。
  **稳健修复（推荐，直接让未配置必开设置弹窗）**：把 `ensureAiConfigured` 末尾改成不依赖 opener 的兜底——
  ```js
  showToast(_t('toast.noApiKeyNotice'), 2800);
  const settingsModal = $('ai-settings-modal');
  if (typeof openAiModal === 'function' && $('ai-settings-open')) {
    openAiModal('ai-settings-modal', $('ai-settings-open'));
  } else if (settingsModal) {
    settingsModal.classList.remove('hidden');   // 浏览器/无 opener 兜底
  }
  return null;
  ```
  改的是 **`assets/js/features/ai.js` 源文件**，改完**必须 `python tools/sync_version.py` 重新 bundle** 再跑门禁。

**注意**：失败 B 可能是**真实产品 bug**（未配置 AI 时没弹设置框，正是项 7/项 4 要修的行为），不是 spec bug。修 App 是正解。修完这条也顺带巩固项 7。

## 8. 环境 / 工具链陷阱（已踩过的坑，勿重蹈）

- **npx 坏了**：`npx playwright` 会从别的项目缓存（`<other-project>/.npm_cache`）解析 → `MODULE_NOT_FOUND`。**永远** `cd ui-tests && node node_modules/@playwright/test/cli.js …`。
- **ui-tests 依赖曾为空**：已用本地缓存修好：`cd ui-tests && npm_config_cache="$PWD/.npm-cache" npm ci --no-audit --no-fund`。若 `node_modules` 再空，重跑此命令（**必须带 `npm_config_cache` 覆盖**，否则又命中污染的全局缓存）。Chromium 浏览器已在 `$LOCALAPPDATA/ms-playwright`，无需再装。
- **webServer 自动起**：Playwright 配置里 `webServer` = `python ../tools/ui_server.py`，baseURL `http://127.0.0.1:${READMD_UI_PORT||28473}`。`ui_server.py` 跑**真实 readmd 后端**，`READMD_DATA_DIR` 指向一次性 `tempfile.mkdtemp(prefix='readmd-ui-test-')` → 未配置 AI 的流程可端到端真测，无需 mock。配置：timeout 45000、workers 1、retries 1；desktop 1440×900、mobile 390×844。
- **代理**：GitHub 走 Clash `127.0.0.1:64409`（端口可能变，连不通先问用户）；大文件 `curl -C -` 断点续传。
- **Bash 陷阱**：`| tail` 会吞掉退出码——看输出文本判断成败，别只信 `$?`。
- **bundle 行号会漂移**：每次 `sync_version.py` 后 `readmd.boot.js` 行号变（本文档里的 boot 行号是快照，仅供定位附近；**以 grep 函数名为准**）。编辑永远改 `assets/js/**` 源文件。
- **工具输出污染**：本会话工具结果常被超大 skills 列表 system-reminder 污染——优先用 Read/Grep/Glob 而非 Bash 看文件，省 token。
