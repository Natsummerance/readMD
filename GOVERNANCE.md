# Project governance

## Current model

ReadMD uses a lightweight maintainer-led model. [Natsummerance](https://github.com/Natsummerance) reviews direction, releases, security reports and merge decisions. Contributors may propose changes through Issues, Discussions and pull requests.

## Decision areas

| Area | Decision method |
|---|---|
| Bug fixes | Reproduction plus focused review |
| Features | Use case, local-first fit and maintainability |
| Localization | Native-language clarity and complete coverage |
| Releases | Regression checks, packaging validation and checksum publication |
| Security | Private advisory review and coordinated disclosure |

## Contribution flow

1. Discuss a substantial idea in Issues or Discussions.
2. Implement it on a focused branch.
3. Add tests or manual verification evidence.
4. Submit a pull request using the template.
5. Address review comments before squash merge.

## Changes to governance

Significant governance changes require a public proposal in Discussions and final maintainer approval. The decision record is the merged governance document.
