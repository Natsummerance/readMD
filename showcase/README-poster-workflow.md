## 一、核心设计哲学与质量底线

1. **真实性第一 (Evidence-First)**：
   - 严禁使用概念占位图、未对齐界面的通用截图或假数据；
   - 每一张海报展示的功能，必须对应 Playwright 在实机环境下采集的真实 UI 或真实数据。
2. **拒绝平庸排版 (No Dead Whitespace)**：
   - 竖版 1080×1440 空间寸土寸金，**严禁缩小图片后不放大文字留下一大片死白区域**；
   - 标题必须具备张力（80px~84px），正文大而舒展（28px~30px），并配有 **Key Specs 胶囊指标条**；
   - 相框横向与纵向自然充满，**严禁图片内部留黑边 (Letterboxing)**。
3. **高内聚低耦合优先**：
   - 剔除琐碎的 UI 微调（如拖动条样式修饰），优先展示系统级、功能性的重磅更新（如桌面伴读生态、矢量 PDF 差分门禁、FastMCP 21 工具链、本地 3D 引力图谱等）。

## 二、五步标准制作流水线 (Pipeline)

### Step 1: 版本增量解析与高内聚过滤
- **输入**：`release/release_notes.md` 或 `git log <prev_tag>..HEAD`。
- **操作**：
  1. 梳理所有功能性提交，过滤纯样式修饰与底层微构；
  2. 将更新提炼为核心主线（如：桌宠拖拽投喂 + 矢量改 PDF + 3D 图谱）；
  3. 在 `showcase/update-<version>/release-delta.json` 中配置卡片清单（建议 16 张，突出主推功能）。

### Step 2: 爆款标题与非AI化文案撰写
- **标题规范**：
  - 采用 `/dbs-xhs-title` 爆款公式（如 #08 好奇缺口型、反常识对比型）；
  - 严格限制在 **20 个中文字符以内**，杜绝多余废话；
  - 例：`把文件拖给桌宠直接打开？这本地MD绝了` (刚好 20 字)。
- **正文规范**：
  - 采用 `/humanizer` 润色，严格执行 **0 破折号、0 机械假大空词汇、0 机械 Emoji 堆砌**；
  - 采用平实、专业、极客而有温度的第一人称/开发者视角讲述真实体验。

### Step 3: 定向实机截图采录与真实性契约
- **截图环境**：
  - Playwright 视口：`width: 1440, height: 900`，`deviceScaleFactor: 2`（视网膜级高清）；
  - 存储位置：`showcase/raw_<version>/<shot_id>.png`。
- **严格对应图文契约**：
  - 谈桌宠投喂，图中必须有桌宠与拖拽悬停高亮；
  - 谈 PDF 矢量修改与差分门禁，图中必须有修改文字、红公章、以及差分热力图/门禁 0 泄漏指标；
  - 谈 FastMCP 工具，图中必须有 21 项工具清单终端与 Agent 直连 JSON-RPC 请求；
  - 谈表格聚类，图中必须有包含跨行跨列合并的复杂报表还原；
  - 谈正文代码块执行，图中必须有就地运行后回填的 Matplotlib 高清图表。

### Step 4: 画报级排版与视觉自检门禁
- **排版渲染**：
  - 运行渲染器读取 `release-delta.json` 生成 1080×1440 高保真大卡；
  - 采用杂志级上文下图排版，加入 Key Specs 胶囊指标组填补间隙；
  - 自动执行 `0 裁剪`、`0 文本溢出`、`SHA-256 溯源哈希` 自动化断言。
- **视觉自检**：
  - 运行 `node showcase/scripts/audit_poster_layout.js`；
  - 检查死白高度（相框到 Footer 间距必须 ≤ 60px），确保内容饱满。

### Step 5: 小红书发布包导出与多端分发
- **导出规格**：
  - 运行 `node showcase/scripts/export_xhs_package.js`；
  - 输出格式：高质量 JPEG（品质 95，1080×1440），单图体积约 180KB~230KB；
  - 生成 `showcase/output/xhs-<version>/artifacts/`：
    - `images/xhs-01-*.jpg` ~ `xhs-16-*.jpg`
    - `title.txt`
    - `body.txt`
    - `topics.txt`
    - `gallery/index.html`（离线快速审阅画廊）

## 三、海报版面视觉规格与规范 (Design Specs)

| 视觉元素 | 规格与尺寸 | 设计意图与要求 |
| :--- | :--- | :--- |
| **画布尺寸** | 1080px × 1440px (3:4) | 小红书官方标准竖屏尺寸，高清晰无压缩 |
| **安全内边距** | 上 40px, 左右 48px, 下 32px | 避免手机边缘被贴边裁切 |
| **主标题 (H1)** | 80px ~ 84px / line-height 1.06 | 衬线字重 600，气势磅礴，第一视觉吸睛点 |
| **正文说明 (.body)** | 28px ~ 30px / line-height 1.55 | 字距微调 0.005em，舒适阅读，阐述功能本质 |
| **呼应卡片 (.callout)** | 宽 290px / 标 21px / 来源 14px | 右上角悬浮，点阵发光，呼应核心技术点 |
| **胶囊指标条 (.spec-strip)** | 17px ~ 18px 胶囊 / 间距 10px | **关键消除死白元素**，展示 3~4 个硬核指标标签 |
| **证据相框 (.frame)** | 满宽 984px / 高 680~740px | 双层微阴影，圆角 10px，无黑边无变形 |
| **页脚信息 (.footer)** | 18px 经典等宽字体 | 包含版本跨度、绿印戳与 12 位 SHA-256 防伪哈希 |

## 四、自动化执行命令参考 (CLI Reference)

```bash
# 1. 验证截图完整性与哈希
node showcase/update-v239/render-deck.mjs --verify-only

# 2. 编译渲染 16 张高清大卡 PNG
node showcase/update-v239/render-deck.mjs

# 3. 运行视觉自检工具 (检测是否有死白或裁剪)
node showcase/scripts/audit_poster_layout.js

# 4. 一键导出小红书发布包 (生成 16 张 1080x1440 JPG 与文案包)
node showcase/scripts/export_xhs_package.js
```

## 五、发布前全量核验清单 (Checklist)

- [ ] **标题字数**：小红书标题严格控制在 20 字以内，具备好奇缺口或情绪共鸣；
- [ ] **正文质检**：无任何破折号（——），无机械 Emoji（🔥⚡🚀），语言口语化自然；
- [ ] **图文匹配**：16 张海报文字所描述的特性与截图画面 100% 对应；
- [ ] **相框质检**：内部截图横向撑满相框，上下无黑边 (Zero Letterboxing)；
- [ ] **版面自检**：无大片空洞空白，大标题、大正文与 Key Specs 胶囊层次分明；
- [ ] **发布包就绪**：16 张 1080×1440 高质 JPG 文件全部生成且大小在 180KB 以上；
- [ ] **离线画廊验证**：在浏览器中打开 `index.html`，确认所有图片均能顺畅预览。
